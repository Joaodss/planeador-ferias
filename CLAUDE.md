# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

A vacation planner: a draggable hour grid per trip, served by a single Go binary (standard library only, no third-party modules). The page in `web/` uses native ES modules with no bundler and no build step. There is no database: each trip is a JSON file on disk. The README, code comments, server error messages, test names and UI strings are in **European Portuguese**. Keep new comments and messages in Portuguese, and add any user-facing text in both languages (see i18n below).

## Commands

```sh
# Run locally (DATA_DIR defaults to ./data, which is gitignored). The password must be at least 10 characters.
PLANNER_USER=eu PLANNER_PASSWORD=uma-palavra-passe go run .
# PowerShell: $env:PLANNER_USER='eu'; $env:PLANNER_PASSWORD='uma-palavra-passe'; go run .

go test ./...                          # server tests (*_test.go)
go test -run TestTripLifecycle ./...   # one Go test
node --test tests/*.test.mjs           # page tests (Node 22+, no npm install)
node --test --test-name-pattern="PT e EN" tests/*.test.mjs   # one page test (a bare tests/ path fails)
node --test --experimental-test-coverage --test-coverage-include='web/js/*.js' --test-coverage-exclude='web/js/main.js' tests/*.test.mjs   # page coverage, as CI measures it
cd e2e && npm ci && npx playwright install chromium && npm test   # Chromium smoke test (the only npm in the repo)
gofmt -l . && go vet ./...             # CI fails if gofmt -l prints anything
go test -run '^$' -bench . -benchmem   # GET/PUT benchmarks (not run by CI)

docker compose up -d --build           # production container
```

- Environment variables:
  - `PLANNER_USER` and `PLANNER_PASSWORD` are required.
  - `DATA_DIR` defaults to `./data` (`/data` in the image) and `PORT` to `8080`.
  - `PLANNER_HOME_TZ` is optional and sets the default second time zone.
- `web/` is embedded with `//go:embed` and loaded into memory once at startup (`loadStatic`), which also injects a `<link rel="modulepreload">` for every `.js` into `index.html` (relative paths, sorted so the ETag is stable). **Restart `go run .` after editing any file in `web/`.** A browser reload alone won't show the change.
- CI (`.github/workflows/ci.yml`) runs on every PR and must pass before merging. It runs all of the above plus `go test -race`, a `go mod tidy` diff check, `staticcheck`, `govulncheck`, `hadolint`, and a smoke test that starts the real Docker image read-only and checks login, `PUT` and `GET`.
- CI also enforces coverage minimums (issue #33): the server total (`awk` on `go tool cover -func`) and lines/functions/branches of `web/js/*.js` without `main.js` (Node's `--test-coverage-*` flags). The minimums are the current values rounded down: raise them in `ci.yml` in any PR that adds tests, and never lower them. `ui/` is outside the glob: it only holds DOM code, and the E2E job covers it.
- The `e2e` CI job (`e2e/smoke.test.mjs`, Playwright + `node:test`, its own `package.json`) builds the real server with a temp `DATA_DIR`, then drives Chromium (`pt-PT`, `Europe/Lisbon`, Google Fonts stubbed): login (wrong password, then right), create a trip, new activity, drag to another day, Undo, day place, general cost, warnings, reload, Sair, switch to EN and sign in again. It fails on any console error or page exception (CSP violations included). It writes the function coverage of `ui/` to the job summary with no minimum (V8 lists only compiled functions, so it overestimates). It relies on element ids and a few PT/EN strings: update it when you rename them. `e2e/` is in `.dockerignore`, and Dependabot bumps Playwright weekly.
- `docker.yml` publishes multi-arch images to `ghcr.io` on pushes to `master` and on `v*` tags.
- The PR template asks you to run both test suites and to try the page in both PT and EN when it changes.
- Go versions differ: `go.mod` declares 1.22, CI uses 1.26 and the Dockerfile 1.27. Dependabot bumps actions, Go and the base image weekly.
- `.gitattributes` forces LF line endings.

## Architecture

### Server (`*.go`, one `main` package)
- `main.go` holds config and startup, `routes.go` the routing, `auth.go` login, sessions and rate limiting, `trips.go` trip files and backups, and `static.go` the embedded page.
- `newServer(cfg)` (`main.go`) creates the data folders, loads the session key and the page, and builds the routes. `routes()` (`routes.go`) uses Go 1.22 `http.ServeMux` patterns (`"PUT /api/trips/{id}"`, `r.PathValue("id")`) wrapped in two middlewares: `secHeaders` (CSP and the other security headers) and `csrfGuard`. Session routes go through `requireSession`, and `tripHandler` validates `{id}`. The mux answers unknown paths with 404 and wrong methods with 405 (with `Allow`), both as plain text; handler errors stay JSON (`fail`). Anything that isn't API falls through to `GET /` (`serveStatic`).
- **CSP:** scripts may load only from `'self'` and `cdnjs.cloudflare.com`, and fonts only from Google Fonts. Add any new external resource to the CSP string in `routes.go`, or the browser will block it. Inline `<script>` is blocked; inline styles are allowed.
- API: `POST /api/login`, `POST /api/logout`, `GET /api/trips` (returns `{user, trips, homeTz}` with an `ETag`; `If-None-Match` gets a 304), `PUT /api/trips/{id}`, `DELETE /api/trips/{id}`. Every request other than GET/HEAD must send `X-Requested-With: planner` (`csrfGuard`). Trip IDs must match `^[A-Za-z0-9_-]{1,64}$`, and `clean.js` exports the same regex as `ID` (used by `backup.js` when importing).
- **The server doesn't know the trip schema.** It stores `trip` as `json.RawMessage` and checks only that `trip.id` matches the URL. New trip fields need no server change.
- On disk, `DATA_DIR/trips/<id>.json` holds `{rev, updatedAt, trip}`. Writes are atomic (temp file, then rename) and serialized by `s.mu`.
- **Record cache (`trips.go`):** `loadRecord` keeps each file's bytes, `rev`, size and mtime in `s.cache` (guarded by `s.mu`) and only rereads a file when a `Stat` shows a new size or mtime, so hand edits still show up. Above `s.maxCache` (16 MB) it keeps only the metadata and rereads the bytes. `GET /api/trips` concatenates the raw records without reparsing them and writes the response after releasing `s.mu`. Its ETag hashes `id rev size mtime` of every file plus user and home zone. `etagMatch` (`routes.go`) compares weakly and ignores a `-gzip`/`-zstd` suffix added by Caddy. Files whose `trip` is not a JSON object are skipped (the page couldn't open them). `PUT` takes `rev` from the cache and writes the record by hand (`json.Compact` of the trip); `PUT` and `DELETE` update or drop the cache entry. `PUT` reads the body with `io.ReadAll` + `json.Unmarshal`, not a `json.Decoder`, which allocated 1.3 MB more per 1.2 MB trip in `BenchmarkPutTrip`. Only an `*http.MaxBytesError` gives a 413.
- **Optimistic concurrency:** a `PUT` sends `{baseRev, trip}`. If `baseRev` differs from the stored `rev`, the server returns 409 with the current record. If the file is gone but `baseRev != 0`, it returns 409 `{deleted:true}`.
- Nothing is ever hard-deleted. `DELETE` moves the file to `backups/<id>/apagada-<timestamp>.json`. Before the first write of each UTC day, the server copies the previous version to `backups/<id>/YYYY-MM-DD.json` and keeps the last 30.
- Sessions use a stateless HMAC cookie `<expiryUnix>.<sig>`. The signing key is `sha256(.session-secret + user + password)`, so changing the password invalidates every session. The cookie lasts 30 days and slides: it is re-issued at most once a day on authenticated API calls. Failed logins are rate-limited to 8 per IP and 40 overall per 10 minutes. The client IP comes from `X-Forwarded-For`, because the app is meant to run behind Caddy.
- `-healthcheck` flag: the binary calls its own `/healthz` (`healthcheck(url)` in `main.go`). The Docker `HEALTHCHECK` needs this because the image is `FROM scratch` and has no shell or curl. `main()` only parses flags, calls `loadConfig(os.Getenv)` (reads and validates the environment), `newServer` and `ListenAndServe`.
- **Side effects are `server` fields** that `newServer` fills with the real values: `now` (clock for sessions, login attempts, `updatedAt` and backup names), `failDelay` (400 ms wait after a failed login), `maxCache`, `writeFile` (`writeAtomic`, used for trips and daily backups) and `log`. Use `s.now()`, never `time.Now()`, in server code. `loadStatic(fsys)` takes the file system (`webFS` in production, `fstest.MapFS` in tests).
- Each server file has its own test file (`auth_test.go`, `routes_test.go`, `trips_test.go`, `static_test.go`, `main_test.go`; the GET/PUT benchmarks are in `trips_test.go`). The shared helpers live in `helpers_test.go`. Tests build a server with `newTestServer(t)`, which calls `newServer` with a temp `DATA_DIR`, sets `failDelay` to 0 and discards the log. `withClock(s, t)` stops the clock at `t` (and returns it, to `add` time), `captureLog(s)` collects the log, and a test can swap `s.writeFile` to simulate a full disk. Every top-level test calls `t.Parallel()`, except `TestWriteJSONEncodeError`, which swaps the global logger. Tests must not change package-level variables. Requests go through `call()` / `authedCall()` against `ServeHTTP` with `httptest`; no real listener is involved. Error paths are tested by breaking the data folder (a folder where a file should be, or the reverse, or `trips/` removed), so they also work on Windows; permission checks are skipped there.

### Page (`web/`)
- `index.html` holds all the markup: the board, the bottom "por agendar" tray, side sheets (`#editor`, `#daysheet`, `#tripsheet`, `#costsheet`, `#warnings`), plus the login and offline screens. It loads `css/app.css` and the single entry point `<script type="module" src="js/main.js">`. The web tests check both paths, and the CI Docker smoke test checks for `js/main.js`. If you rename either file, update `index.html`, `tests/web.test.mjs` and `ci.yml` together.
- **`js/main.js` lists what every module does.** Logic without DOM lives in `js/` and imports nothing from `js/ui/`; UI lives in `js/ui/`. **`ui/` modules only read fields, call `js/` functions and write the DOM** (issue #30): any rule, calculation or validation goes in a pure function in `js/` with tests. For example `backup.js` (`parseBackup`, `mergeTrips`), `excel.js` (the three sheets as arrays, without SheetJS), `tripform.js` (`validateTrip`, `tripFields`, `newTrip`, `applyTripEdit`), `moves.js` (`keyMove`, `dropSlot`, `resizeEnd`), `costSummary`/`tripStats` (`costs.js`), `sortWarnings` (`warnings.js`), `laneLayout` (`span.js`) and `newBlock`, `duplicateBlock`, `removePlace`, `setDayPlaces`, `routeSummary`, `dateRangeLabel` (`trip.js`). New activities always come from `newBlock`, so the defaults live in one place. **No module does anything when it is imported** (issue #29): each `ui/` module exports one `init…()` with its event listeners, and `main.js` calls them in order, then `connectUI(…)`, `initSync()`, `I18N.apply()` and `boot()`. Keep new top-level code inside an `init…()`. `tests/imports.test.mjs` imports every module (except `main.js`) in Node without a DOM and checks that each `ui/` module (except `dom.js`) has exactly one `init…()`.
- **Shared mutable state lives in `S`** (`state.js`), because an ES module can't reassign a `let` imported from another module. `T()` returns the active trip.
- The `ui/` modules still import each other in cycles (`board.js` ↔ the sheets), which is safe because nothing runs at import. DOM helpers (`$`, `toast`, `announce`, `isMobile`, `PXM`/`refreshSlot`, `fillTzSelect`) are in `ui/dom.js`; `util.js` is pure. **Model functions take the trip** instead of reading the active one: `money(t, v)` (formerly `fmt`), `blockCostPP(t, b)`, `placeById/placeName(t, id)`, `addPlace(t, name)`, `findBlock(t, id)`, `blocksOf(t, date)`, `moveTo(t, id, date, start)`, `toTray(t, id)`, `dayCostPP(t, date)` and `computeWarnings(t, L0)`. The UI passes `T()`. Only `state.js` knows which trip is active.
- **Mutation pattern:** call `pushHistory()`, mutate `T()` in place, then call `commit()` from `sync.js`. An undo point is the active trip's JSON (`{id, trip}`), capped at 60; pass `pushHistory(true)` to snapshot the whole store (`{store, id}`) when creating, duplicating, deleting or importing trips. `undo()` (`sync.js`) calls `restoreLast()` (`state.js`, which restores the point and reopens its trip) and then commits. The history never touches the DOM: `render()` calls `refreshUndo()` (`ui/board.js`) to enable the Undo button; call it yourself after a `dropHistory()` that is not followed by a render. `commit()` marks the store dirty, debounces a save (1.2 s) and calls the `render` hook (`ui/board.js`). `commit(true)` is for `input` events in text fields: it saves the same way but renders only after a 150 ms pause. `change` events, drag and the arrow keys keep the synchronous `commit()`, because code after them reads the new DOM. Use `dropHistory()` when it turns out nothing changed. Editors that fire on every keystroke use a `snap` flag so they push history only once per edit session.
- `render()` rebuilds the board, tray and stats from state, recomputes the warnings and refreshes any open sheet without stomping the focused input. It computes `boardLayout` once for the board (`BL`) and once in trip time (`L0`, the same object unless the board is in the second zone), then passes `L0` to `computeWarnings(t, L0)` (`warnings.js`) and `fillDay(false, L0)` (in a refresh the day sheet's place and "until" selects are an unapplied draft: their options are rebuilt but the choice is kept), and `F` to `fillEditor(full, F)`. Each of these still computes its own when called without them. Per-day costs come from `dayTotalsPP(t)` (`costs.js`) in one pass. `.day-col` has `content-visibility:auto`, so style and layout run only for columns near the screen. That was most of a long trip's render. It also makes each column paint-contained: anything drawn outside a column is clipped beyond `overflow-clip-margin` (6px) and painted under the next column.
- **Sync (`sync.js`)** holds the network calls, saving and the session, and touches neither the DOM nor `ui/`. The UI plugs in through `connectUI({render, closeSheets, toast, announce, saveState, showLogin, showApp, showOffline})` (no-ops by default; the tests pass `mock.fn()` spies), and `initSync()` adds the `visibilitychange`/`beforeunload` listeners (`onVisibilityChange(hidden)` is exported). The decisions are pure exported functions: `pendingOps(snap, synced)` (what to `DELETE` and `PUT`), `applyPutResponse(st, t, js, status, body)` (200/409/409 deleted/413) and `sameRevisions(trips, revs, serverTrips)` (for the refetch). `tests/sync.test.mjs` runs it against a fake in-memory server behind a mocked `fetch`, with `mock.timers` enabled once for the whole file; the login and offline screens and the Sair button live in `ui/login.js`, which calls `signIn`/`signOut`. Every request goes through `api(method, path, body, headers)`, which adds `X-Requested-With`. A 401 anywhere except `/api/login` ends the session (`endSession` → the `showLogin` hook) and throws `ApiError('auth')`; check for it with `isAuthError(e)`. The private `Map`s `synced` (the JSON string last confirmed by the server) and `revs` (its revision) drive dirty detection. The `PUT` body is concatenated on purpose, so it carries exactly the snapshot string that goes into `synced`. A trip that appears in `synced` but not in the store is sent as a `DELETE`. On a 409 the client discards its local copy, takes the server version, clears undo history and shows a toast. A 413 (bodies over 2 MB) is marked synced so it doesn't retry forever. `doSave` serializes each trip once (`snapshot()`) and, if no `commit()` ran during the save (`edits` counter), reuses that snapshot to recompute `S.dirty`. The page also refetches when the tab becomes visible, and saves when the tab is hidden. The refetch sends the last applied `ETag` (`listTag`) in `If-None-Match` and does nothing on a 304. It stores a new ETag only once the list has been applied or found identical, never while there are unsaved changes.
- **Times** are minutes from midnight of the block's `date` column and can exceed 1440 when the board crosses midnight. `view(t)` (`span.js`, re-exported by `trip.js`) derives `T0`, `span` and `T1` from `dayStart` and `dayEnd` (hours; `dayEnd < dayStart` means the day ends after midnight). The grid snaps to 15 minutes.
- **The board hours only control what is shown.** A block may start at any hour and last several days. `span.js` (pure, tested in `tests/span.test.mjs`) works in absolute minutes from the trip's first midnight: `segments()` cuts a block into the visible piece of each column (`cutTop`/`cutBot` mark where it continues, drawn as a zig-zag edge), and `hiddenEdge()` places a marker (`.hid-chip`) at the nearest column edge for a block with no visible part. `boardLayout()` (`span.js`, re-exported by `trip.js`) applies both to the whole trip, and only marks hidden blocks whose `date` is inside the trip (always checked against trip dates, never against the board columns: `sh` can be 0 in another zone when it is exactly 24 h behind). Overlap warnings compare absolute times, so they catch overlaps across days. Costs and the day sheet still belong to the block's own `date`.
- **Time zones (`tz.js`):** `trip.tz` is an optional IANA zone, and board times are always the trip's local time. Times are never converted when `tz` changes. An extra hour column shows a second zone. That zone comes from the device's choice (`localStorage` `ferias-home-tz`), else the server's `PLANNER_HOME_TZ` (sent as `homeTz`), else the browser's zone. `secondTz(t)` computes **one offset per trip**, taken at noon UTC on `t.start`. `resolveTz` (tested in `tests/tz.test.mjs`) accepts a full name or just the city. Chrome and Node list old CLDR names (`Asia/Calcutta`), so `TZ.all` swaps in the current ones (`RENAMED`) and a city missing from the list is tried as `<region>/<City>`. The time zone fields (trip, second zone, activity) are `<select>`s like the other dropdowns (issue #43): `fillTzSelect` (`ui/dom.js`) fills them from `tzGroups(cur)` (one `<optgroup>` per region, translated through `tzRegions`, options labelled by city so typing jumps to it).
- **Board in the second zone:** clicking a city in the grid corner switches the board to that zone (per device, `localStorage` `ferias-view-home`). Stored `date`/`start` stay in trip time. Only the view changes. `viewOffset(t)` is 0 in trip time. `boardFrame(t)` (`trip.js`) returns `{ds, d0, sh, off}`: the board's columns (dates in the board zone) and the shift `sh` that `segments`/`hiddenEdge`/`boardLayout` take as their last argument. `toBoard`/`fromBoard` convert one block through `toFrame`/`fromFrame` (`span.js`, tested in `tests/span.test.mjs`). The grid, drag, arrow keys and editor work in board time and convert with `fromBoard` before writing. Day places, day costs, the day sheet, warnings and Excel export stay keyed by trip dates and call `boardLayout` without a shift. `boardFrame` adds non-clickable "outside the trip" columns (at most `EXTRA=2` on each side) when a block starts before or after the trip in board time.
- **Trip shape** (defaults are filled in by `normTrip`, so old data keeps loading). `normTrip` calls `cleanTrip` (`clean.js`, pure, tested in `tests/clean.test.mjs`) on every trip loaded from the server or imported. It coerces numbers, drops unknown `status`/`cat` values, replaces invalid or duplicate IDs and moves blocks with no valid `date` to the tray. The server doesn't validate the schema, so this is the only guard against malformed data. Even so, render a status only through `statusLabel()` (`util.js`) and pass every free-text field through `esc()` before it goes into `innerHTML`:
  - Basic fields: `id, name, start, end` (ISO dates), `dayStart, dayEnd, tz?, people, currency, budget?`.
  - `places[{id,name,c}]` and `dayPlaces{date:[first, ...stops, last]}` (up to `MAX_DAY_PLACES`, no place twice in a row; `setDayPlaces`, `splitDayPlaces`). The day header shows only `dayEnds()` (first and last); the stops show in its tooltip, and warnings and `clashesOn` accept every place of the day (issue #41).
  - `blocks[]` (scheduled activities) and `tray[]` (the same objects without `date` or `start`).
  - A block may have its own `tz` (issue #42, checked by `cleanTrip`). `date`/`start` stay in trip time: the editor shows and reads the day and time in that zone (`editorTime`/`fromEditor`, via `toZone`/`fromZone` in `trip.js`, with the offset of the block's own date), and the block on the board adds its local time when the zone is not the board's (`blockZoneTime`). Without a trip `tz` it is ignored.
  - `costs[{id,label,amount,per:'total'|'pp',cat?,date?,paid?}]` (a cost with no `date` is a general cost).
  - Optional `costCats`. When it is absent, translated defaults are used, and `ownCats()` copies them onto the trip the first time they are edited.
- Enum IDs that are persisted are Portuguese: status `ideia/reservar/reservado/pago` and cost categories `alojamento, transporte, …`. These are stored data, so never rename them. Only their labels are translated.
- Excel export loads SheetJS from cdnjs lazily, only when the user clicks it. Backup and import use the format `{version:2, trips}`. Import merges trips by `id`.
- `localStorage` keys: `ferias-lang`, `ferias-active-trip`, `ferias-hide-sleep`, `ferias-home-tz`, `ferias-view-home`. Trip data never lives in `localStorage`. The server is the only store.

### i18n (`web/js/i18n.js`) and the page tests
- `pt` and `en` dictionaries, with `pt` as the fallback. A value can be a string with `{placeholders}`, an array or object, or a function (used for plurals and word-order differences). In code, call `tr(key, params)`. In static HTML, use the `data-i18n`, `data-i18n-ph`, `data-i18n-title` and `data-i18n-aria` attributes. `I18N.set(lang)` only switches and stores the language; `I18N.apply()` writes the `data-i18n*` texts and `<html lang>` (main.js at startup, the language button after `set`, followed by `render()`). The module touches no DOM on its own.
- `tests/web.test.mjs` checks several things:
  - PT and EN have the same keys, with matching types, list lengths and `{placeholders}`.
  - Every key used via `tr('…')` or a `data-i18n*` attribute exists.
  - Every module parses.
  - Every import resolves to a real export.
- Each logic module has its own test file (`tests/<module>.test.mjs`): `util`, `state`, `trip`, `costs`, `tz`, `warnings`, `span`, `clean`, `sync`, `backup`, `excel`, `tripform` and `moves`, plus `imports.test.mjs`. In extracted code with branches, write one statement per line: with several per line, Node's line and branch coverage stop meaning much. None of them needs a DOM. Modules that read `localStorage` load `tests/env.mjs` as the **first import**: it provides `localStorage` (contents in `store`; set `storage.fail = true` to make every call throw) and `navigator.language` (`pt-PT`). It is not a `*.test.mjs` file, so it doesn't run on its own. Tests that depend on the local time zone set `process.env.TZ = 'Europe/Lisbon'`, which Node applies immediately.
- `web.test.mjs` reloads `i18n.js` to test the language choice. The first load is the real module, and the others are `data:` URL copies. A `?n=` copy would count as the same file and hide the real module's coverage.
- The test parses the source with regexes, so keep to these forms:
  - **Single-quoted literal keys** inside `tr(...)`.
  - **Single-line `import { a, b } from '…'`** statements.
  - Exports declared as `export function`, `export const` or `export { … }` at the start of a line.

## Build and deploy notes
- The Dockerfile copies only `go.mod`, the root `*.go` files and `web/`. A Go subpackage or a `go.sum` (if a dependency is ever added) would need its own `COPY` line.
- The runtime image is `FROM scratch` and runs as UID 65532 with a read-only root filesystem, no capabilities and a 64 MB memory limit. Data lives in the `/data` volume.
